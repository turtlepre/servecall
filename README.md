# 서브콜

혼자 하는 테니스 서브 연습용 인·아웃 판독기입니다. 코트 반대편에 세운 안드로이드 폰 카메라가 공이 떨어진 곳을 찾아, 블루투스 이어폰으로 "인", "아웃. 길게 30센티"처럼 알려 줍니다.

- 앱 설치 없이 크롬에서 여는 웹앱입니다. 서버가 필요 없는 정적 파일이고, 영상은 폰 밖으로 나가지 않습니다.
- 서비스라인(길이)과 센터라인·사이드라인(좌우)을 모두 판정합니다.
- **실제 코트 시험은 아직 적습니다.** 밤 조명 아래 두 세션의 화면 녹화를 분석해 고쳤습니다(아래 "실제 코트 기록"). 정확도 숫자는 모두 합성 영상으로 잰 값입니다.

## 동작 방식

1. **코트 맞추기**: 화면에서 서비스 박스 모서리 4곳을 찍으면, 그 주변에서 흰 라인을 찾아 1픽셀 안팎으로 보정합니다. 보정된 모서리로 코트의 다른 라인 위치를 계산해 흰 점선으로 겹쳐 보여 주므로, 점선이 실제 라인과 겹치는지 보고 맞았는지 확인할 수 있습니다.
2. **공 찾기**: 박스 주변만 잘라서 매 프레임 "새로 나타난 노란 점"을 찾습니다. 흰 라인 위에서도 공이 보이도록 밝기 대신 노란 정도(min(R,G) − B)를 씁니다. 카메라가 살짝 떨려 제자리의 공이 한두 픽셀 움직여 보이는 것은 무시합니다.
3. **바운드 찾기**: 공의 궤적이 꺾이는 순간을 찾고, 중력·공기저항·회전을 넣은 3D 비행 모델을 카메라에 맞춰 프레임 사이에 일어난 바운드의 위치와 시각을 계산합니다.
4. **서브의 첫 바운드인지 확인**: 바운드 직전의 궤적을 거꾸로 따라가, 그 공이 네트 너머에서 날아온 것이 확실할 때만 판정합니다. 두 번째 바운드, 펜스에 맞고 돌아온 공, 굴러다니는 공은 부르지 않습니다.
5. **판정**: 공은 바닥에 약 4~5ms 동안 닿아 있으면서 눌리고 앞으로 10cm쯤 미끄러집니다. 이 **접촉 자국**이 박스(라인 포함)에 조금이라도 닿으면 인입니다. 자국의 위치와 길이는 바운드 전후 속도에서 계산합니다.
6. **음성**: 효과음과 한국어 음성으로 알립니다. 소리는 폰에 연결된 이어폰으로 나갑니다.

## 준비물

- 안드로이드 폰 + 크롬 (아이폰 사파리에서도 열리지만 시험해 보지 않았습니다)
- 삼각대. 높을수록 정확합니다. 펜스에 거는 클램프가 있으면 2.5~3m까지 올릴 수 있습니다.
- 블루투스 이어폰
- 노란 테니스공
- 밝은 낮. 카메라 셔터가 1/250초보다 느려지면(해 질 무렵, 야간 조명, 실내) 공이 번져서 찾지 못합니다. 그럴 때는 앱이 화면과 말로 경고합니다.

## 올리기 (HTTPS 주소 만들기)

폰 크롬은 **https:// 주소에서만 카메라를 허용**합니다. 아래 파일을 정적 호스팅에 올리면 됩니다(`servecall-web.zip`에 같은 파일이 들어 있습니다). `test/` 폴더는 올리지 않아도 됩니다.

```
index.html  styles.css  manifest.webmanifest  icon.svg  icon-192.png  icon-512.png  icon-maskable-512.png  sw.js  src/
```

**GitHub Pages (무료)**

1. GitHub에서 새 저장소를 만들고(예: `servecall`), 위 파일들을 업로드합니다.
2. 저장소 Settings → Pages → Branch를 `main`, 폴더를 `/ (root)`로 두고 Save.
3. 1~2분 뒤 `https://<아이디>.github.io/servecall/` 주소로 접속합니다.

**Netlify Drop**: app.netlify.com/drop 에 폴더를 끌어다 놓으면 https 주소가 바로 나옵니다. 주소를 계속 쓰려면 계정에 연결하세요.

폰의 **크롬 앱**에서 주소를 연 뒤 오른쪽 위 메뉴(⋮)를 아래로 내려 "앱 설치" 또는 "홈 화면에 추가"를 누르면, 홈 화면 아이콘으로 앱처럼 전체 화면으로 열립니다. 링크를 카카오톡이나 Claude 앱 안에서 누르면 그 앱 속 브라우저로 열려 이 메뉴가 없습니다. 그때는 메뉴에서 "Chrome에서 열기"를 고르거나, 크롬 앱에 주소를 직접 입력하세요.

**인터넷이 약한 코트**: 한 번 열면 앱 전체가 폰에 저장되어, 그다음부터는 인터넷이 없거나 약해도 열립니다(연결이 2.5초 안에 답하지 않으면 저장된 사본을 씁니다). 집에서 한 번 열어 본 뒤 코트에 가세요.

- 저장된 사본은 늘 한 버전 전체입니다. 인터넷이 되는 곳에서 앱을 열면 몇 초 뒤 파일 전체를 새로 받아, 저장된 사본을 통째로 바꿉니다. 그래서 신호가 약해 저장된 사본으로 열 때는 새 버전과 예전 버전 파일이 섞이지 않습니다.
- 다만 새 버전을 올린 직후 약 10분 동안은, 브라우저가 기억하고 있던 예전 파일과 새 파일이 섞여 열릴 수 있습니다. 화면이 반응하지 않으면 앱을 완전히 닫았다가(최근 앱 목록에서 밀어서 닫기) 다시 열고, 그래도 같으면 10분쯤 뒤에 여세요.
- 파일을 새로 올린 뒤에는 인터넷이 되는 곳에서 앱을 한 번 열고 5초쯤 기다리세요. 그래야 코트에서도 새 버전이 열립니다.
- 주소를 조금 다르게 열어도(예: 끝에 다른 경로가 붙은 주소) 인터넷이 없으면 앱 첫 화면으로 옮겨 줍니다.

## 사용법

### 1. 카메라 두기

서브를 넣는 박스를 기준으로, **공이 빠져나가는 방향의 반대쪽**에 둡니다. (아래는 오른쪽 절반에서 듀스 박스로 넣을 때입니다. 애드 쪽은 좌우를 바꾸세요.)

| 위치 | 설명 |
|---|---|
| **A** 맞은편 뒤 코너 | 내가 서는 쪽 사이드라인을 따라 반대편으로 가서, 베이스라인 뒤 1~2m · 복식 라인 바깥. 가장 안전합니다. |
| **B** 맞은편 옆 | 반대편 서비스라인을 그대로 연장한 곳, 복식 라인 바깥 2m. 박스와 가까워 더 정확합니다. 옆 코트와 붙어 있으면 방해가 될 수 있습니다. |

- 보통 삼각대(1.5~1.7m)라면 **B**가 낫고, 2.5m 이상 올릴 수 있으면 A·B 모두 좋습니다.
- 펜스 뒤에 붙여 세우면 공에 맞을 걱정은 없지만 박스에서 멀어져 오차가 조금 커집니다.
- 공이 날아가는 쪽(서브 방향의 연장선)이나 맞은편 베이스라인 한가운데는 피하세요.
- 서비스 박스 전체와 주변 2~3m가 화면에 들어와야 합니다. 화면 밖에 떨어진 공은 판정하지 못합니다(B 위치에서는 3m 넘게 긴 서브가 그렇습니다).
- 폰은 가로로 고정합니다.
- 바람에 흔들리지 않게 고정하세요. 1픽셀 안팎의 떨림은 견디지만(코트에 공이 수십 개 굴러다녀도 괜찮습니다), 떨림만큼 판정 위치도 흔들립니다. 카메라가 아예 움직였다면 다시 맞춰야 합니다. 판정 화면의 흰 점선이 코트 라인에서 벗어나 있으면 카메라가 움직인 것입니다.

### 2. 소리 테스트

이어폰을 카메라 폰에 연결하고 [소리 테스트]를 누른 뒤 서브 자리까지 걸어가 보세요. 2초마다 숫자를 읽습니다. **카메라와 서브 자리는 20~28m 떨어져 있어**, 보통 이어폰의 블루투스 범위(공식 10m, 야외에서 시야가 트이면 그 이상)를 넘을 수 있습니다. 끊기면 아래를 시도해 보세요.

- 카메라를 B 위치로 옮기기 (서브 자리까지 약 20m)
- 카메라를 높이 올리기 (몸이나 지면에 신호가 덜 막힙니다)
- 설정 → 알림을 "효과음만"으로 하고 폰 스피커 볼륨을 최대로

### 3. 시작

1. [카메라로 시작] → 카메라 권한 허용
2. 화면에서 서비스 박스 모서리 4곳을 순서대로 터치합니다. 왼쪽 위에 지금 찍을 모서리가 표시됩니다.
   ① 네트·센터라인 ② 네트·사이드라인 ③ 서비스라인·사이드라인 ④ 서비스라인·센터라인
   - **①은 네트와 센터라인(가운데 라인)이 만나는 모서리**입니다. 카메라에서 가장 가까운 모서리가 아닙니다. 안내 상자의 그림은 서버 쪽에서 본 모양이라 카메라 화면과 방향이 다를 수 있으니, 화면에서 네트를 먼저 찾으세요.
   - 네 곳을 찍으면 박스 둘레에 라인 이름(네트·사이드라인·서비스라인·센터라인)이 나옵니다. **실제 라인과 맞는지 꼭 확인하세요.** 시작 모서리를 잘못 고르면 이름이 한 칸씩 밀려 나옵니다(예: 센터라인에 "네트").
   - 이름이 실제 라인과 다르면 점을 다시 찍을 필요 없이 버튼으로 고칩니다. **[이름 돌리기]**는 네 이름을 한 칸씩 돌리고, **[센터↔사이드]**는 센터라인과 사이드라인 이름만 맞바꿉니다. 점은 그대로 있고 번호만 바뀝니다.
   - 앱이 순서를 스스로 바꾸지는 않습니다. 자동으로 바로잡는 기능을 시험해 보니, 손가락 오차만으로 바르게 찍은 순서를 바꾸는 일이 생겨서 뺐습니다.
   - 흰 라인의 **바깥쪽** 모서리가 경계입니다(라인에 닿으면 인이므로). 사이드라인은 안쪽의 단식 라인입니다.
   - 손가락 굵기만큼 어긋나게 찍어도 라인 자동 맞춤이 라인을 찾아 보정합니다. 라인을 찾지 못한 쪽은 찍은 위치를 그대로 쓰고, 어느 라인인지 알려 줍니다.
   - 복식 라인에 잘못 찍으면 단식 라인으로 옮기고 알려 줍니다. 단, 카메라가 낮거나(1.6m 이하) 코트 옆(B)에 있어 두 사이드라인이 화면에서 손가락 오차만큼밖에 떨어져 있지 않으면, 어느 쪽을 찍었는지 알 수 없어 단식 라인을 찍은 것으로 봅니다. 그때 복식 라인에 찍었다면 네트 쪽 사이드 모서리가 라인을 따라 0.6~0.8m 어긋납니다(인·아웃에는 거의 영향이 없지만 카메라 높이 계산이 흔들립니다). **사이드 쪽 두 점은 확대창으로 안쪽(단식) 라인에 맞추세요.**
   - 네트 쪽 두 점은 네트 아래에 라인이 없어서 라인을 따라서만 보정됩니다. 확대창으로 네트 바로 아래에 맞추세요.
   - 네 곳을 다 찍으면 박스 둘레에 라인 이름이, 그 바깥에 흰 점선(복식 라인, 반대쪽 박스, 베이스라인의 예상 위치)이 나타납니다. 이름과 점선이 실제 코트와 맞으면 잘 맞은 것입니다.
   - 찍은 점을 끌면 손가락보다 천천히 움직여 세밀하게 맞출 수 있고, 확대창으로 확인할 수 있습니다. 안내 상자가 점을 가리면 상자가 투명해집니다.
3. [완료]를 누르고 서브를 넣습니다.

판정 화면에는 마지막 판정, 최근 낙하 지점 지도(서버 쪽에서 본 모양), 오늘의 인·아웃 통계가 나옵니다.

- **들리는 말**: "인" / "인. 라인 근처" / "아웃. 길게 30센티" / "아웃. 옆으로 20센티" / "아웃. 센터 쪽 40센티" / "놓쳤어요"
- **"놓쳤어요"**: 공이 네트를 넘어온 것은 봤지만 낙하지점을 판정하지 못했다는 뜻입니다(화면 밖에 떨어졌거나, 바운드 순간에 공이 몇 프레임 안 보였거나, 네트 너머에서 온 공인지 확실하지 않은 경우). 틀린 위치를 부르는 것보다 낫다고 보고 이렇게 했습니다. 드물게 옆 코트에서 튀어 넘어온 공에도 이렇게 말할 수 있습니다.
- **아무 소리도 없으면** 대개 네트에 걸린 것입니다. 다만 공이 바운드 앞뒤로 0.2초쯤 계속 안 보였거나 아예 잡히지 않았을 때도 조용합니다.
- **경고음과 함께 "화면이 꺼져서 판정이 멈췄어요" / "카메라 화면이 멈췄어요" / "카메라가 꺼졌어요"**: 판정이 멈췄다는 뜻이니 폰을 확인하세요. 카메라가 꺼진 경우는 앱이 스스로 다시 켜고 "카메라가 다시 켜졌어요"라고 합니다. 화면이 완전히 꺼지면 브라우저가 멈춰서 이 말조차 못 할 수 있습니다.
- **화면 꺼짐**: 판정하는 동안 앱이 화면을 켜 두려고 합니다. 절전 모드 등으로 이 기능이 거부되면 시작할 때 화면과 말로 알려 주니, 그때는 휴대폰 설정에서 화면 자동 꺼짐 시간을 10분 이상으로 늘리세요. 화면이 꺼지면 카메라와 판정도 멈춥니다.
- **절전 화면**: 화면을 거의 검게 덮어 배터리를 아낍니다. 판정은 계속됩니다.
- **통계**: 오늘 넣은 서브만 셉니다. [기록 지우기]를 누르면 그 뒤부터 다시 셉니다.
- **감도**: 공을 놓치면 민감하게, 엉뚱한 판정이 나오면 둔하게.
- **분석 보기**: 분석 영역(점선 사각형), 공 후보(파란 원), 추적 중인 궤적(분홍 선), 처리 속도와 프레임 시각의 종류를 보여 줍니다.

### 영상 파일로 시험하기

코트에서 폰으로 서브를 찍어 와서 [영상 파일로 테스트]로 열면, 같은 방식으로 모서리를 맞추고 0.25~1배속으로 재생하며 판정합니다. 실제 코트에서 감도를 맞춰 보거나, 판정이 틀린 장면을 다시 확인할 때 씁니다.

## 판정 기준

- 박스: 가로 4.14m(싱글 사이드라인 바깥쪽 ~ 센터서비스라인 반대편 가장자리, 센터라인 5cm는 두 박스 모두에 속함) × 세로 6.40m(네트 ~ 서비스라인 바깥쪽).
- 공이 바닥에 닿아 있는 동안의 접촉 자국이 박스에 닿으면 인입니다. 빠른 서브의 자국은 진행 방향으로 약 10cm, 폭 약 4~5cm입니다. 그래서 서비스라인을 살짝 넘겨 튄 것처럼 보이는 공도, 처음 닿은 곳이 라인이면 인입니다.
- 접촉 시간은 4.5ms로 가정합니다(하드 코트에서 테니스공의 일반적인 값 4~5ms). 실제 접촉 시간이 이보다 1ms 길면 앱이 찍는 낙하지점이 공 진행 방향으로 1.5~2.5cm 밀리고, 라인까지 거리는 평균 1cm쯤 "아웃 쪽"으로 치우칩니다(1ms 짧으면 반대). 공이 더 오래 닿는 클레이 코트에서는 이만큼 아웃 쪽으로 치우친다고 보면 됩니다.
- 자국과 라인 사이가 10cm 이내면 "라인 근처"라고 덧붙입니다. 이 범위는 카메라 판정도 틀릴 수 있다는 뜻으로 받아들이세요.
- 아웃은 벗어난 방향(길게 / 옆으로 / 센터 쪽)과 자국에서 라인까지의 거리를 알려 줍니다.
- 네트에 걸린 서브, 렛(네트 맞고 들어간 공)은 구분하지 못합니다. 렛도 박스에 들어가면 "인"이라고 합니다.

## 정확도 (시뮬레이션)

실제 코트 영상이 없어서, 코트·네트·공 비행(공기저항, 속도의 제곱에 비례하는 회전력)·바운드(접촉 시간 3.5~5.5ms 무작위)·카메라를 재현한 합성 영상으로 검증했습니다.

조건: 위치마다 서브 30개(쏘는 속도 시속 50~180km, 플랫부터 킥 서브까지, 한 번 넣고 약 4초 뒤 다음 서브), 모서리 터치 오차 1.5px 뒤 라인 자동 맞춤, 프레임 시각 흔들림 1ms, 프레임 5% 누락, 720p, 셔터 1/1000초.

node test/accuracy.js --n 30 --click 1.5 --jitter 1 --drop 0.05 --snap

**실제 코트에서는 이보다 나빠집니다.** 합성 영상에는 렌즈 왜곡, 흔들리는 나무, 지나가는 사람, 옆 코트의 공이 없습니다. 또 시험용 공은 앱이 가정한 것과 같은 식으로 날고 튑니다(같은 공기저항 계수, 4.5ms를 중심으로 한 접촉 시간, 같은 접촉 모델). 가정이 조금 다를 때의 영향은 위 표에 있지만, 실제 공이 이 모델과 다르게 움직이는 만큼의 오차는 여기 잡히지 않습니다. 처음 쓸 때는 영상 파일 모드로 몇 개를 확인해 보고 감도를 맞추는 것을 권합니다.

### 실제 코트 기록 (밤 조명, 화면 녹화 분석)

두 세션(4분 반, 25분)의 화면 녹화를 분석했습니다. 인조잔디 코트, 조명 아래, 셔터 1/120초(앱이 경고)였습니다.

- 두 세션 모두 모서리를 **카메라에서 가장 가까운 모서리(서비스라인·센터라인)부터** 찍어 순서가 한 칸 어긋나 있었습니다. 안내 그림(서버 쪽 시점)의 ① 위치를 카메라 화면에 그대로 옮긴 것으로 보입니다.
- 첫 세션은 이 때문에 카메라가 네트 너머로 계산되어 **판정이 하나도 없었습니다**. 같은 녹화를 올바른 순서로 다시 분석하면 판정 8번, "놓쳤어요" 5번이 나옵니다.
- 둘째 세션은 25분 동안 47번 판정했고 "놓쳤어요"는 2번이었습니다. 인·아웃은 박스 모양이 같아 맞게 나왔지만, 방향과 거리가 엉뚱했습니다("센터 쪽"은 실제로 길게, "길게"는 실제로 옆으로). 올바른 순서로 다시 계산하면 인 26, 길게 아웃 11, 옆으로 아웃 10이었습니다.
- 녹화 화면을 올바른 순서로 다시 분석하면 판정이 31번에서 54번으로 늘었습니다(화질이 떨어지는 녹화라 실제 폰보다는 적게 잡힘). 두 계산 모두 판정한 34개 중 33개가 인·아웃과 방향이 같았습니다.
- 이 결과로 **박스 둘레의 라인 이름 표시**와 이름을 직접 고치는 **[이름 돌리기]·[센터↔사이드]** 버튼을 넣었습니다. 같은 순서로 찍는 경우는 브라우저 시험에 들어 있습니다.
- 한때 넣었던 순서 자동 바로잡기는 뺐습니다. 검토에서 손가락 오차(축마다 8~13px)만으로 바르게 찍은 순서를 몇 %의 확률로 뒤집는 것이 확인되었고, 라인 위치를 근거로 판단하는 방법도 시험했지만 같은 문제가 남았습니다.
- 같은 검토에서 낮은 카메라의 라인 자동 맞춤이 손가락 오차를 복식 라인 터치로 잘못 보고 네트 쪽 모서리를 크게 옮기는 문제를 찾아 고쳤습니다(위 표).

알려진 한계 (시뮬레이션에서 확인한 것):

- **네트 1m 이내나 베이스라인 근처에 떨어진 공**: "놓쳤어요"가 자주 나오고, 가끔 조용합니다. 네트 바로 앞은 공이 네트 너머에서 왔다는 것을 확인할 만큼 오래 보이지 않고, 베이스라인 쪽은 화면 가장자리라서입니다.
- **바운드 앞뒤로 공이 0.15~0.2초 넘게 안 보이면** 조용할 수 있습니다.
- **다른 공이 낙하 지점 바로 옆에서 움직이면** 그 서브가 "놓쳤어요"가 될 수 있습니다.
- **공 바로 옆에 노란 점이 바운드 직전 몇 프레임 생기면**(반짝이는 물체 등) 드물게 낙하 위치를 크게 틀릴 수 있습니다. 모든 서브 옆에 이런 점을 일부러 넣은 시험(2,880개)에서 4개가 1.2~5.6m 틀렸습니다.
- **먼 카메라(펜스 코너)에서 검출 위치가 1.5px쯤 흔들리면** 위치가 0.5m 넘게 틀린 판정이 30fps에서 약 2% 나옵니다(60fps에서는 0.4%).

| 첫 글자가 잘림 | 설정 → "이어폰 끊김 방지"를 켭니다(기본 켜짐). |
| 아무 소리도 없음 | 먼저 박스 둘레의 라인 이름이 실제와 맞는지 확인(모서리 순서가 틀리면 판정을 거의 못 합니다). 그다음 [분석 보기]에서 공이 파란 원으로 잡히는지 확인. 안 잡히면 감도를 민감하게, 줌을 당기거나 카메라를 가까이. |
| 아웃 방향이 이상함(예: 옆으로 나간 공을 "길게") | 모서리 순서가 어긋난 것입니다. 인·아웃은 맞게 나와도 방향과 거리가 틀립니다. [다시 맞추기]를 누르고 박스 둘레의 라인 이름이 실제와 맞도록 [이름 돌리기]나 [센터↔사이드]를 누르세요. |
| "놓쳤어요"가 자주 나옴 | 공이 떨어지는 곳이 화면 안에 있는지 확인. 60fps가 되는지 확인(분석 보기 화면 아래 표시). 감도를 민감하게. 공이 네트를 넘기 전부터 화면에 보이도록 네트 쪽도 넉넉히 담기. |
| 엉뚱한 판정 | 감도를 둔하게. 분석 영역 안에 움직이는 것(사람, 나무, 옆 코트)이 적게 카메라 방향 조정. |
| 라인 근처가 자주 틀림 | 카메라를 높이 올리기, 60fps, [다시 맞추기]로 흰 점선이 라인과 겹치는지 확인. |
| "화면이 꺼져서 판정이 멈췄어요" | 화면을 다시 켜면 이어집니다. 휴대폰의 화면 자동 꺼짐 시간을 10분 이상으로, 절전 모드는 끄세요. |
| "카메라 화면이 멈췄어요"가 계속됨 | [끝내기] 후 다시 시작. 다른 앱이 카메라를 쓰고 있지 않은지 확인. |
| 분석 보기에 "화면 시각(부정확)"이 보임 | 브라우저가 프레임 촬영 시각을 주지 않는 경우입니다. 안드로이드 크롬 최신 버전을 쓰세요. |
| 메뉴에 "홈 화면에 추가"나 "앱 설치"가 없음 | 크롬 앱이 아닌 곳(카카오톡·Claude 앱 속 브라우저)에서 열린 경우입니다. 메뉴에서 "Chrome에서 열기"를 고르거나 크롬 앱에 주소를 직접 입력하세요. 크롬에서는 오른쪽 위 ⋮ 메뉴를 아래로 내리면 있습니다. 삼성 인터넷이라면 아래쪽 ≡ → "현재 페이지 추가" → "홈 화면"이지만, 크롬을 권합니다. |
| 파일을 새로 올렸는데 예전 화면이 나옴, 또는 화면이 반응하지 않음 | 인터넷이 되는 곳에서 앱을 열고 5초쯤 기다린 뒤, 앱을 완전히 닫았다가(최근 앱 목록에서 밀어서 닫기) 다시 여세요. GitHub Pages는 올린 뒤 약 10분 동안 브라우저가 예전 파일을 그대로 쓸 수 있으니, 그 사이라면 10분쯤 지나 다시 여세요. |

## 개발

```
index.html, styles.css, manifest.webmanifest
icon.svg, icon-*.png  앱 아이콘 (PNG는 홈 화면용)
sw.js           인터넷 없이도 열리게 앱 전체를 한 버전 단위로 저장 (새 파일을 src/에 추가하면 SHELL 목록에도 추가)
src/
  app.js        화면, 카메라, 모서리 맞추기, 판정 표시, 멈춤 감시와 경고
  pipeline.js   프레임 처리 흐름, 분석 영역, 첫 바운드 확인, 판정 못 한 서브 알림
  detector.js   새로 나타난 노란 점 찾기
  tracker.js    궤적 연결, 바운드(꺾임) 찾기
  refine.js     3D 비행 모델로 바운드 위치 보정, 궤적 거슬러 올라가기
  bounce.js     접촉 모델: 꼭짓점 높이, 접촉 자국
  timing.js     프레임 시각 고르기(TimeSource), 흔들림 제거(FrameClock)
  snap.js       흰 라인 찾아 모서리 보정
  geometry.js   호모그래피, 카메라 위치·초점거리 추정
  court.js      박스 규격, 판정, 음성 문구
  voice.js      음성·효과음, 블루투스 유지
  store.js      설정·기록 저장
test/
  sim.js        합성 코트·공 비행·바운드·카메라 렌더러
  unit.js       단위 테스트
  events.js     알림 규칙 검사: 이상적인 검출 위치로 서브 수천 개 (서브당 한 번만 알림, 네트는 조용히, 나중 바운드·펜스에서 돌아온 공·서브가 아닌 공은 부르지 않기, 60fps 잡음)
  snap-check.js 라인 자동 맞춤 정확도(낮은 카메라 포함)
  scenarios.js  합성 영상으로 보는 상황별 검사(네트, 먼 낙하, 구르는 공, 느린 서브, 가려진 바운드, 놓인 공, 셔터, 애드 코트, 모델 차이)
  accuracy.js   카메라 위치·프레임별 정확도 측정
  make-video.js 브라우저 시험용 합성 영상(Y4M, WebM)
  e2e.js        크롬 실시간(가짜 카메라)·터치·모서리 순서·영상 파일·카메라 꺼짐·오프라인 시험
  serve.js      로컬 정적 서버
```

```bash
npm test
```

```bash
node test/make-video.js && node test/e2e.js
```

`npm test`는 단위 테스트, 알림 규칙, 라인 맞춤, 시나리오, 빠른 정확도 검사를 차례로 돌립니다(약 8분, 대부분 시나리오). `e2e.js`는 Playwright와 Chromium이 필요하고, 시험 영상(약 560MB)을 `test/out/`에 만듭니다. 로컬에서 화면을 보려면 `node test/serve.js` 후 `http://localhost:8123/`을 엽니다(localhost는 http에서도 카메라가 허용됩니다).

정확도 측정에 쓸 수 있는 옵션: `--only A25,SIDE16`(카메라 위치), `--fps 30`, `--n 30`, `--click 1.5`(터치 오차 px), `--snap`, `--radius 24`(자동 맞춤이 라인을 찾는 거리 px, 기본 14, 앱은 휴대폰에서 약 24), `--jitter 1`(ms), `--drop 0.05`, `--shutter 250`, `--mirror`(애드 코트), `--court clay`, `--tauc 3.5`(접촉 시간 ms 고정), `--drag 0.8`(공기저항 배율).
